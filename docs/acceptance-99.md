# 99% 可用率验收基准

目标尚未达成。自动化回归测试的通过率与线上可用率分别报告，不能相互替代。

## 固定分母

每个验收页面在执行前登记：平台、版本/采集时间、场景、档案事实、预期字段和预期组件值。已登记的失败、超时、漏识别和不支持控件计入失败，不允许执行后移出分母。附件上传、协议、最终提交以及档案无答案的字段预先单列。

- 有效填写率 = 组件实际接受且内容正确的字段数 / 预先登记的可填写字段数。
- 错填率 = 错误写入字段数 / 尝试写入字段数；验收目标为 0。
- 整页完成率 = 所有登记必填项正确完成的页面数 / 验收页面数。
- 人工干预、耗时、重复点击、恢复次数单独统计。

99% 的目标必须绑定指定网站、页面集合和时间区间。建议固定至少 100 个独立页面场景、累计 1000 个字段，覆盖多段经历、下拉、级联、日期区间和页面重新渲染；不能用重复运行同一个简单输入框凑分母。这是观测指标，不是统计上保证未来全部网站都有 99% 成功率。

## 当前自动化证据

`test/browser/real-components.spec.js` 使用安装锁定版本的 React + Ant Design 和 Vue + Element Plus，读取组件应用状态以验证学校 ID、多选 ID、文本、日期和区间。其他浏览器用例提供异常恢复、特殊平台 DOM 和安全约束回归。

运行 `npm run test:browser`，机器可读结果写入 `test-results/report.json`。测试结果只表示锁定组件及样本的回归情况。真实站点列表尚待用户提供，当前没有可报告的线上有效填写率。

## 规则持久化

动态发现的唯一 ID 弹层规则保存于扩展本地存储，按浏览器消息发送页的 origin 隔离，并按路径、控件结构和标签区分。每个 origin 最多 50 条，保存时校验 ID 选择器，30 天过期；每次使用前重新校验，失效丢弃。只保存定位规则，不保存表单填写值或简历。
